# 从路线海报 / 轨迹里提数据：清单与坑

## 1. 图片取数脚本骨架

```python
from PIL import Image
p = r"D:\...\route_poster.jpg"
im = Image.open(p).convert("RGB")
print(im.size)                     # 先看尺寸
regions = {                        # 按比例估区块，再微调
    "head":    (40, 140, 1240, 300),    # 顶部数据条
    "map_top": (60, 270, 1240, 480),    # 地图上半（地名标注密集区）
    "profile": (60, 1030, 1240, 1290),  # 海拔剖面（含峰值标号与端点海拔）
    "cards":   (40, 1290, 1240, 1580),  # 逐日卡片
}
for k, (l, t, r, b) in regions.items():
    c = im.crop((l, t, r, b))
    c = c.resize((c.width * 2, c.height * 2), Image.LANCZOS)
    c.save(f"crop_{k}.png")
```

- 放大倍数：文字 2 倍起，**地名/海拔数字建议 3–4 倍**（4 倍最保险）。
- 裁完必须真的用读图能力看一眼，不要靠 OCR 文本推断。
- 中间产物放工作区 `analysis/`，确认数据无误后删除。

## 2. 必须提取的字段

| 字段 | 说明 | 易错点 |
| --- | --- | --- |
| 总里程 | 保留 2 位小数 | 与逐日之和比对，差 0.05 以内算一致 |
| 累计爬升 / 下降 | 带符号 | 两者之差 = 全程净升降 ≈ 终点海拔 − 起点海拔 |
| 命名垭口数 | "7 个"这类 | 剖面图上 P 标号可能少于该数（原图漏标 P2 之类）→ 脚注说明 |
| 最高点 | 名称 + 海拔 | 名称易错（桃/姚、错/措、孜/子） |
| 逐日：距离 / 爬升 / 下降 / 用时 / 最高海拔 | 卡片原文 | 逐日"最高海拔"必须与剖面对应日的峰值相等 |
| 逐日：水源 / 营地 / 终点 | 卡片原文 | 海拔数字常与"垭口海拔"混用 |
| 起点/终点海拔 | 剖面图横轴两端的标注 | 常被截断，需放大看 |

## 3. 一致性校验（必做）

1. `Σ 逐日距离 ≈ 总里程`
2. `Σ 逐日爬升 ≈ 累计爬升`，`Σ 逐日下降 ≈ 累计下降`
3. `全程最高点海拔 = 逐日最高海拔的最大值`（若不等，说明某日数值有笔误 → 取图中重复出现的那个）
4. `当日终点海拔 = 上日终点海拔 + 当日爬升 − 当日下降`（±30 m 内视为一致）
5. 用第 4 条反推起点海拔，与剖面图横轴起点标注比对

## 4. 剖面图折线的构造

没有 GPX 时按"关键点 + 自然起伏"手绘，规则：

- 每天必有：起点、当日最高点（= 日最高海拔）、当日终点三点；
- 在长上坡段插入 1–2 个中间台阶，长下坡段插入 1–2 个缓台，避免直线太假；
- 相邻两天的接点海拔必须相同（营地海拔一致）；
- 全线上限 = 最高点海拔，其余所有点严格小于它；
- 剖面 y 轴范围取 `[起点海拔 − 300, 最高点 + 200]` 取整到 500 的倍数。

## 5. 地名常见字形混淆

- `错 / 措 / 错`：藏语湖，川西这两个字混用，按原图照抄
- `桃 / 姚 / 兆`、`孜 / 子`、`垭 / 哑`、`沟 / 构`
- `达纳错`、`斯达纳错` 这类音译长名，逐字放大确认后再落图
