# 常见坑 · 版式与排版

> 从 `SKILL.md`「常见坑」拆出。触发词：右栏高度 / 文字对比度 / 文案折行 / 卡片不等高 /
> 手机长图 / 窄版排版 / 表格溢出 / 类名撞车 / 行宽 / 地图与右栏不协调。
> 配套：`references/legend-and-color.md`（配色四档灰阶）、`scripts/shoot_long_png.py`（长图导出）。

---

## 0. 通用：改完必须重出所有下游产物

**一改地图内 SVG 的字号/图例，必须同时重出三样东西**：
`build_<线路>.py`（HTML）→ `shoot_<线路>_png.py`（两版长图）→ `render_map_hi.py`（全线高清地图）。
漏了高清图，用户放大看的就是旧字号版本。
改了**底图**（配色 / bbox）则还要在前面加上 `make_terrain.py`。

## 1. ⚠ 地图列与右栏的「协调」：两个独立的坑都要治

### 坑 1：右栏比地图列高/矮，两边底边不齐

**首选根治：改底图 bbox 的纬度跨度，让地图天然等高 —— 而不是用 CSS 硬拉。**

地图画布宽高比**完全由 bbox 决定**（`IW, IH` 由 DEM 裁剪范围算出）。所以
「地图高度」是一个**可以在源头设计的量**，不该用 CSS 事后补救。流程：

1. 用探针量右栏自然高度 `H_rail` 与内容可用宽 `W_content`
   （`.page` 1120 − 左右 padding 各 26 = **1068**）。
2. 定地图列宽 `W_map`（如 714，左侧留 14 px gap → 右栏得 340）。
3. **反解需要的画布宽高比** `r = H_rail / W_map`（946/714 = **1.325**）。
4. 用 Web Mercator 关系算纬度跨度：
   ```
   Δy/Δx = (lat_span / cos φ) / lon_span        # φ = bbox 纬度中心
   → lat_span = lon_span × r × cos φ
   ```
   例：`0.460 × 1.325 × cos(42.5231°) = 0.4492°`；围绕**轨迹纬度中心**等距展开
   → `LAT0/LAT1 = 42.2985 / 42.7477`（原 42.3350/42.7150，**只扩纬度、不动经度**）。
5. ⚠ **必须同时改 `build_map.py` 与 `make_terrain.py` 的 bbox**（两处共用同一组常量，
   只改一处会导致轨迹与底图整体错位）。改完**重跑 `make_terrain.py`**
   （DEM 瓦片按块缓存，扩范围只多下几块，本例 2m47s）。
6. 验算：`轨迹 bbox 是否完整落在新 bbox 内` + `新画布比例 ≈ r`。

好处：① 地图**铺满**整框，零死白；② 不裁掉任何轨迹；③ 顺带多看到南北方向地形。
代价：要重跑一次地形渲染（约 2–3 分钟）。

**次选（做不到改 bbox 时才用）：CSS 硬拉。**

```css
.mapwrap{display:grid;grid-template-columns:minmax(0,714px) minmax(0,1fr);
         gap:14px;align-items:stretch}   /* ← stretch 让地图跟着右栏等高 */
.mapbox{...;height:100%}                  /* ← 不写就跟着内容高 */
```

⚠ 但**拉高后框内必然多出一块死白**（实测 `.mapbox` 946 vs SVG 798 → 上下各 74 px），
用户会直接说「上下区域很丑」。若坚持走这条路，必须让 SVG **垂直居中**把余量均分：

```css
.mapbox{...;display:flex;align-items:center;background:#F1EDE5}
.mapbox svg{width:100%;height:auto;display:block}   /* ⚠ 不要用 position:sticky */
```

底色取地形边缘同系浅色（`#F1EDE5`），别用纯白/浅灰 —— 但**这只是美化，治不了根**。

### 坑 1b：右栏字号相对地图「过轻」

地图占位大、色块重，右栏字号偏小会像脚注。但右栏高度已被地图锚定，
**放大字号必须从行距/间距里换空间**，否则右栏会反超地图、底边又不齐。做法：

| 元素 | 原 | 改 |
|---|---|---|
| `.lg` 字号 / `margin-bottom` | 12.8 / 6 | **13.6 / 4.5** |
| `.lg .sw` 高 | 26 | **25** |
| `.lg .nm em` | 11.8 | **12.4** |
| `.rbox h3` | 13.5 / `margin-bottom:10` | **14.2 / 9** |
| `.kp` 字号 / padding | 12.9 / `5px 0` | **13.6 / `4px 0`** |
| `.sch` / `.sch th` / `td` padding | 12.2 / 11 / 3.8 | **12.9 / 11.6 / 3.4** |
| `.rnote` | 12.2 | **12.8** |

结果：字号全部放大，右栏高度反而从 946 微降到 **945**（分日方案 503→486），仍与地图等高。

### 坑 2：右栏内容被面板右边缘裁掉

症状：「好走/最难/冰川」等标签只显示一半。根因是
**`.mapwrap` 固定 px 列宽之和 > 版心内容宽**，而 grid 列**不会随内容自动收缩**。

实测：`.page` 1120 宽、左右 padding 各 26 → 内容可用宽只有 **1068**；
列宽写成 `744px 340px`（合计 1098）时，右栏被撑到 `right=1168`，而内容右界 1119，
**溢出 49 px**。

两道保险一起上：
1. **列宽给 `minmax(0, …)`**：`minmax(0,714px) minmax(0,1fr)`；
   ⚠ 纯 `1fr` 不算数，`1fr` 的默认最小值是 `auto`，内容宽就会顶开列宽，**必须写 `minmax(0,1fr)`**。
2. 右栏行内三段按「可收缩度」排优先级：
   ```css
   .kp{display:flex;...;min-width:0}
   .kp b {flex:0 0 auto;min-width:58px;white-space:nowrap}        /* 里程，固定 */
   .kp .nm{flex:1 1 auto;min-width:0;overflow:hidden;
           text-overflow:ellipsis;white-space:nowrap}             /* 描述，先被省略 */
   .kp .el{flex:0 0 auto;white-space:nowrap;padding-left:6px}     /* 难度标签，永不压 */
   ```
   这样超宽时是**描述**被截断，而不是把整个容器顶出去。

### 验证必须用探针量，不能靠肉眼

注入 `<script>` 取 `document.querySelector('.page')` 的
`right − paddingRight` = **内容右界**，再取 `.rail` / `.segx .el` 的
`getBoundingClientRect().right`，**后者必须 ≤ 前者**。
只看截图永远发现不了「差 8 px」这种级别的溢出。

> 探针模板见 `SKILL.md` §自检，或 `references/self-hosted-terrain.md` 附的测量脚本片段。

## 2. 窄栏文案：字数按列宽反推

- **文案字数要按列宽反推**：窄栏 `209 px ÷ 11.8 px ≈ 17 个汉字位`，
  减去加粗名称占宽才是说明文字上限；超一个字就变成"…高 / 程"两行孤字。
- **信息表格会溢出卡片**：右栏窄表格给 `table-layout:fixed` + 显式 `nth-child` 列宽
  + `overflow:hidden;text-overflow:ellipsis;white-space:nowrap`，否则"累计"等末列被裁。
- **海拔显示要统一取整**：同一座山在剖面标注、关键点表、地名卡里必须同一个数
  （如都写 `894` 而非一处 `893.9`），用一个 `fmt_ele()` helper 统一格式化。

## 3. 对比度与灰阶

**文字灰阶要过对比度**：四档相近的浅灰看着"精致"，实测常只有 **2.2–3.1:1**
（远低于 AA 的 4.5:1），而它们恰好用在小字上。做法：一档统一"最浅可用"下限，
把四档重新拉开；配色细则见 `references/legend-and-color.md` §5。

## 4. 逐日卡等高

**逐日卡两张高度不等时把 `margin-top:auto` 给难点框**：
`.day{display:flex;flex-direction:column}` + 难点框 `margin-top:auto`，
卡片底部的"难点"行就对齐了；**不要**给卡片整体 `flex:1` 硬撑（空白会转成内部空洞）。

## 5. ⚠ CSS 类名撞车 —— 长页面必踩

**症状**：某段文字只占左边一小条、右边空一大块。

**实战案例**：新增的「雪线说明块」里写 `<p class="src">`，而 `.src` 早就被
「参考资料」section 定义成 **3 列 grid**
（`.src{display:grid;grid-template-columns:repeat(3,1fr)}`）
→ 那段依据文字被塞进第一列（约 1/3 宽），右侧空出 2/3，用户直接说「排版较差」。

**规矩**：
1. 新增块内的**每个类名都要先 grep 一遍**，确认没被别处占用：
   `grep -n "\.<name>" build_*.py`。
2. 单文件生成的长页面（本工程所有 CSS 都内联在 `build_*.py` 顶部）
   **优先给新块的类名加前缀**（`.slsrc`），而不是复用通用名。
3. 更稳的写法是**用后代选择器限定作用域**（`.snowline .src{...}`），
   但要小心"覆盖不彻底"—— grid 的 `grid-template-columns` 不会因为没写就消失，
   必须在后代选择器里显式重置 `display:block`。**换新类名比覆盖旧样式安全。**
4. **短名最容易撞**：`.hl` / `.nm` / `.el` / `.sub` / `.foot` / `.src` ——
   新块里宁可写长一点。

## 6. 行宽用 px 给，别用 `ch`

`ch` 是「0」字符宽，**中文一个字约 2ch** → 写 `max-width:76ch` 实际只能放约 38 个汉字，
远比预期窄。**判据：中文正文一行 35–50 字最舒服**，即 `max-width ≈ 字号 × 45`。
正文 12.6 px → 620 px 左右。

⚠ **带底色/边框的段落不能跟着限宽** —— 高亮块的背景只铺到 max-width 边界，
右侧空一块比"行长过长"更刺眼。写法：

```css
.snowline p:not(.hl):not(.slsrc){max-width:620px}   /* 只管无底色纯文字 */
.snowline .hl{...;max-width:none}                    /* 底色块铺满容器 */
```

手机断点里再 `max-width:none` 解除（窄屏本来就窄，不该再限）。

## 7. 手机版是另一套排版

- **必须另出一版手机长图**：2344 px 宽的图在 390 px 手机上正文只有 2 屏幕像素。
  给同一份 HTML 加 `@media(max-width:900px)` 断点，再渲染一版 860 宽（430 CSS × 2）。
- **⚠ 无头 Chrome 有最小窗口宽 500，绝不能按窗宽反推裁剪区间**：
  `--window-size=430` 时 `clientWidth` 实测是 500 而非 430。
  **一律按像素量版心边界裁**（`getBoundingClientRect()` 取 `.page` 的 left/right/height）。
- **SVG 图内文字会跟着版心缩，窄版必须重出一份，且倍率要算不要猜**：
  固定 viewBox 缩放到容器宽度，版心 1032 → 370 时缩放比 0.37。
  倍率 = `目标CSS宽 / viewBox宽`；算出后再决定字号是否需要单独放大。
- **窄版是另一套排版，别指望桌面文案直接缩下去**：卡片内宽只有 ~167 px（≈13 个汉字），
  长标签必然折行并留下"…最高 / 峰）"这种孤字 → 用 `.donly` / `.monly` 双份文案，
  或干脆改短。
- **剖面端点标签会撞上两端刻度数字**（桌面版同样存在）：终点标签锚在右端、`30` 刻度也在右端，
  原本只差 4–7 px，读出来是「…25430」。
  修法：刻度行归一档、端点标签改 `anc="axis"` 锚到轴内侧。

## 8. 文字与图形的层级

- **主线路一减细，点位符号必须跟着收**：线细了点没变，视觉层级会反过来，
  下一次反馈就是"点太大"。用一个 `PS = 0.85` 系数统一乘全部符号半径与标签字号。
- **所有 POI 的 `dx/dy` 偏移量必须与标注字号同源**：字号一改，固定的 `dx=48` 就从
  "贴着图标"变成"悬空在远处"。改字号时要把 `dx/dy` 按同比例缩（例 dx 48→34、dy ×0.68）。
  判据：`dx` 应约等于图标半径 + 一个字的宽度。
- **地图标注不要手工逐个调 dx/dy，写成自动避让**：真实返工过两轮 ——
  ① 西侧点全用 `anc=end` 左对齐，导致文字都压向左侧标注密集区；
  正解是**按点位相对画布中心的方向自动选锚点**（左半区 `start`、右半区 `end`），
  再叠一个"已占位矩形"碰撞检测，冲突就沿法线方向让位。
- **比例尺要放在轨迹的"空白扇区"，不是固定角**：竖长线路左下角可能正压着密集段标注
  （南天山北线 48 km 冰川段全堆在左中）。做法：把候选位置（四角 + 上下中）各算一次
  "与轨迹点/已有标注的最小距离"，取最大的那个。

## 9. ⚠ 按像素量版心：阈值不能取「整幅的一半」

注入探针底色后量版心边界时，别写

```python
cols = np.where(off.sum(axis=0) > 0.5 * h)[0]     # h = 整幅高
rows = np.where(off.sum(axis=1) > 0.5 * w)[0]
```

**窗口开得比内容高很多时，列覆盖率永远够不到 0.5**（本例窗口 9000 → canvas 18000，
内容只占 8105 = 45%），`cols` 直接空，报的错是"探针底色可能被覆盖"，
但真正原因是阈值 —— 很容易往错误方向查半天。

→ **两遍量**：先以极低阈值（如 `> 0.02 * w`）定**行区间**，
再在行区间内用 `> 0.5 × 区间高` 定列。

配套两条：

- **`--window-size` 的高度别贪大**：`canvas 高 = win_h × scale`，
  超过约 **16384** 时 Edge 截图会静默出问题（本例 18000 直接失败）。
  先量一次内容高度，再取 `win_h ≈ 内容高 + 余量` 即可，
  并断言 `版心宽 == 设计宽 × 倍率`（本例量到 860 = 430 × 2 ✓）。
- **版心不一定居中**：实测手机版心 430 落在 x 140–1000（左 70 / 右 100 CSS，不对称）。
  别用"居中"去反推裁剪区间，**一律用像素量出来的边界裁**。

## ⚠ Edge headless `--screenshot` 相对路径静默失败

`--screenshot=out/x.png` 可能不产出任何文件也不报错。**输出一律用
`Path(...).resolve()` 绝对路径**；截完立刻断言 `out.exists() and size>0` 再往下游走。
